# 花费：记忆插件自己花了多少模型钱

>
> 对应版本：D131（2026-11-09）。代码：`packages/dsh/src/ports/llm.js`（调用和计数）、`packages/dsh/src/ports/budget.js`（账和护栏）、`packages/core/src/config/defaults.js` 的 `budget`（预设）、`packages/dsh/src/host/config.js` 的 `budget` / `llm`（价目、输出上限、模型）。

一句话：**插件自己在后台调模型（第一眼、提炼、夜间整理……），都走 DSH 的模型通道、用的是 DSH 账号余额；向量（嵌入）默认在本机的 Ollama 上算，不花钱（D127 起也可以不用嵌入，或者接外部服务）。** 她回你的话是 DSH 自己的会话，不是插件调的。管理页「设置 → 后台花费」能看到今天按用途分开的账和最近 30 天，和她的聊天、整个账户比。

## 1. 插件自己调模型的地方

全部用 `deepseek-flash`（精确 id，在允许清单里，不跟随 DSH 的默认模型），思考关（模型支持的最低档），temperature 0.2。每次调用的量是按代码里的上限和提示词长度估的（中文约 1–1.5 字一个 token）；实际的数在管理页里。

| 用途（管理页上的名字） | 代码里的用途 | 什么时候调 | 每次大约 | 次数由什么决定 |
|---|---|---|---|---|
| 第一眼 | `glance` | 别人在她在的地方说了话，感知入库以后按场合排队看一眼（一次最多 12 行新消息 + 6 行上文） | 输入约 0.7–2.5k（提示词约 1k 字，常能命中缓存），输出上限 600，实测约 60 | 群里和私聊的消息量；一对一和对她说的先看。超了每天上限还有 150 次预留 |
| 提炼 | `extract` | 一段对话安静下来（隔 20 分钟或满 25 条 / 4000 字）成段以后提炼成事实、经历 | 输入约 3k 固定前缀（D123 起多了「什么值得写成事实」一节，约 +0.5k，能命中缓存）+ 一段对话最多 4000 字和背景，输出 ≤ 4000，一般 0.5–1k；D123 起一时的小事不再写成事实，输出预计少一两成 | 对话段数（次数不变）。预算不让跑就推迟（10 分钟起翻倍，最多 6 小时），不丢。输出写到 4000 被截断的那一段（D141）不当成提炼完，对半拆开各提炼一次：这一段多花 2 次调用，两半里再有截断的接着拆（到一条消息为止）；被截断的那次的花费照记 |
| 夜间整理 | `sleep` | 每天 04:30（错过了启动时补跑）：对照原话纠错（D122）、复核、泛化、反思、印象、故事线、社区、成长块、回头问问、回顾做事的经验（D124）；还有提炼的复核 | 每次输入几 k 到 10k，输出 80–700 × 每批条数。纠错一次核 4 条，输入约 4–6k（每条带来源、之后的原话、她做过的，约 1–1.5k），输出 ≤ 900 | 每晚最多 = 各步上限之和（D138，`sleep.maxLlmCalls` 默认 null）：复核 1 + 纠错 2（`sleep.correct.maxCalls`）+ 泛化 2（`sleep.generalize.maxCalls`）+ 反思 2 + 印象 2 + 回头问问 1 + 故事线 1 + 社区 1 + 日记和成长 1 + 回顾经验 1（`sleep.lessons.maxCalls`）= 宽松 / 不设上限档 14 次，节省档只做必要项（复核、纠错、印象、故事线）6 次；没活干的步不调。`sleep.maxLlmCalls` 写成数字就按它封顶，日记和成长、回顾经验的名额先留出来，前面的步骤用不到。纠错没有到期该核的就不调；节省档也做纠错（它在必要项的第 2 步：记错的认知每一轮都会被注入，一晚最多 2 次、约 0.007 元，不值得省）；日记缺了几天时一次调用补最多 3 天（`sleep.diary.maxDaysPerNight`），输出多 300 token / 天 |
| 摘要 | `summary` | 一个地方的对话空闲 10 分钟后，写一句「今天到目前为止」 | 输入最多 80 条感知，约 1–2k；输出 ≤ 200 | 有对话的场合数 × 停顿次数 |
| 第二段评估 | `appraise` | 要进她上下文的记忆，第一段没拿准的，交给模型判断这一轮能不能用 | 输入约 2k（含对话窗口），输出 160 × 条数 + 120 | 宽松档：所有拿不准的；节省档：只在对她说、真正等待、有意回想时 |
| 外发审视 | `review` | 她要在公开场合说的话，初筛撞上了记忆才送审（D113 起非公开目标不送审） | 输入约 1.5k，输出 ≤ 260 | 公开场合发言里撞上记忆的；每天单独预留 100 次 |
| 改写 | `rewrite` | 预取回想时，读懂对她说的话：把「那个」「他」和人称换掉，写成 1–3 条线索，另外给出关于谁、原话里的时间词、提到的场合、要一条还是一串（D154 起回一小段 JSON） | 输入约 1–1.5k（D154 起提示词带四个例子，约 1k 字，能命中缓存），输出上限 300（合成的例子约 30–60，三条长线索时约 120） | 对她说的消息；节省档关掉 |
| 看过的媒体 | `perceive` | 她看了一段视频 / 图片，之后把她的想法和回话摘成一句「她看到了什么」 | 输入 ≤ 1500 字想法 + 750 字回话，输出 ≤ 200 | 她看媒体的次数 |

### D122–D126 对花费的影响（估计）

- **纠错（夜间整理，`sleep`）**：一晚最多 2 次、每次输入约 5k、输出约 0.5k，按空闲价约 0.007 元 / 晚（输入未命中 5k × 1 元 + 输出 0.5k × 4 元，每百万 token），一个月约 0.2 元。它有自己的 2 次，算在每晚的总数里（D138 起总数默认是各步之和，各步互不挤占）。
- **提炼（`extract`）**：调用次数不变（按对话段数），固定前缀长了约 0.5k（命中缓存时 0.02 元 / 百万，几乎不算钱）。代码规则（核验第 14 条）在库副本 11-05 晚到 11-08 的 377 条事实上预演：13% 当时不会成为事实（旧数据里模型几乎每条都给 imp 5，代码只拦 imp 低的）；大头要靠提示词按刻度给 imp、少写琐事，输出 token 预计少一两成（事实行是输出的大头）。真实的变化等上线后在「后台花费」按天的提炼输出 token 和库里每天的事实条数看，回填到第 7 节。
- **回顾做事的经验（D124，夜间整理第 11 步，`sleep`）**：只在上次以来有新东西（反复没成的工具、主人纠正过她对自己的认知）时调一次（`sleep.lessons.maxCalls` = 1，算在每晚的总数里；D138 起这一次的名额先留出来，前面的步骤用不到），输入约 1–2k（工具名、次数、短的出错说明、纠正前后两句、已有的经验最多 30 条），输出 ≤ 500；没有新东西不调。约 0.002–0.004 元 / 次，一个月最多约 0.1 元。节省档只做纯代码的那一半（定哪些经验放进常驻区），不调。
- **她自己记经验、工具结果、想起经验（D124）**：都不调模型——经验是她用 `memory_note` 在她自己的回合里写的（算在她的聊天里），工具成没成是宿主数的，想起是代码按范围挑的。**但会让她的聊天多一点 token**（算在「她的聊天」里，不在后台花费里）：「你做事的经验」对上时每轮 ≤ 2 条、≤ 220 字；常驻区「【你的经验】」有常驻的经验时 ≤ 200 字（冻结、能命中缓存）；先没成后成了的提醒每个会话每个工具一句（约 70 字）。
- **「有记忆 / 没记忆」评测（D126）**：不调模型（替身端口），在临时库里跑，几秒钟，不花钱。
- **用法说明的写法（D125）**：不调模型。默认的「详细指引」是原文，`memory_note` 的说明后面多了经验那一行，加上三个经验参数的说明，工具定义一共多约 220 字（约 150–250 token），随工具定义在她每次调模型时发出去，通常命中缓存（命中按 0.02 元 / 百万 token，几乎不算钱；没命中按 1 元 / 百万，一千次调用约 0.2 元）。「只讲目的」的常驻区和工具说明比「详细指引」短约 200 字。

## 2. 不花钱、或者不算在这里的

- **回想本身不调模型**：五路召回、融合、工作记忆、关口①第一段、外发守护都是本机计算。只有上表里的第二段评估和改写会调。
- **向量（嵌入）**：管理页「设置 → 嵌入」选三档（D127）。本机 Ollama 上的 `qwen3-embedding`，不花钱，只占显卡或 CPU（管理页「设置 → 显卡」）；不用嵌入，不花钱也不调任何服务（回想走 L3）；接外部服务（OpenAI 兼容），按它自己的价收费，这里不算，保存时会提醒，换模型要把全部记忆重新算一遍向量，按量计费的服务这一次也要花钱。
- **她的回话**：DSH 自己的会话（QQ 桥接、网页会话），花费在「她的聊天」里，是 DSH 的花费，不是插件的。插件注入进去的记忆块会让她的会话多一些输入（之后每一步按缓存命中重复计费），这部分算在她的聊天里，靠注入量的上限管（设计 §10.4）；上限跟着花费档位（D133，见第 5 节的「回想注入」两行）。
- **整个账户**：同一个 DSH 账号上所有会话（她的、你写代码的、子代理……）加上后台。插件只用它来估「余额还能撑几天」。

## 3. 怎么记账，准不准

- **准的：次数和 token 数。** 每次调用结束，DSH 的流里有一个用量块（`inputTokens` 未命中缓存的输入、`cacheReadTokens` 命中缓存的输入、`outputTokens` 输出；DSH 的 DeepSeek 适配器用的是 Messages 接口，`inputTokens` 不含命中的那部分）。插件原样记下。写缓存的 token（`cacheWriteTokens`，DeepSeek 没有单独的价）按未命中算。
- **失败的调用也记**（超时、中止、出错）：算一次调用、一次失败；DSH 报了用量的照样记 token 和钱（结果丢了，钱照样花了）。DSH 没报用量的就只有一次失败——这种情况下 DeepSeek 可能已经按处理了的输入计费，插件看不到。没发出去的（没配模型、模型不在允许清单里、后台在退避）不算调用。
- **DSH 没报用量的成功调用**：按字数估（约 1.5 字一个 token），单独记成「估的」，管理页会写出有几次。
- **估的：元。** 按配置的价目折算（第 4 节）。北京时间工作日 9–12、14–18 点按高峰价；DeepSeek 法定节假日全天按空闲价，插件不认节假日，所以那几天会略高估。扣多少以 DeepSeek 账单为准。主聊天用的是 `deepseek-account`（账号登录）路由，它是否和 API key 路由完全同价没核实过（`docs/调研/v2/v0/v0-价目与模型.md` §9）；桥接账本按同一张表折算的和余额变化量级吻合。
- **记在哪**：`<数据目录>/host-budget.json`，只有数字，按本机的日子分天，重启不丢。今天的：放行次数（失控上限按它算）、按用途的 `{calls, failed, estimated, in, cached, out, yuan}`、合计、高峰时段的元、她的聊天、整个账户、被护栏挡下的次数。历史留 **90 天**，每天一行：次数、失败、token、后台元（含高峰部分）、按用途的小账、被挡次数、她的聊天元、整个账户元。
- D120 以前的文件：按用途只记了放行次数（管理页标「只记了次数」），历史只有每天的元，照样读。

## 4. 价目，和怎么改

现在的价目（元 / 百万 token，`deepseek-flash`，2026-11-01 从 DeepSeek 官方价目页核对，见设计附录 G 和 `docs/调研/v2/v0/v0-价目与模型.md`）：

| | 空闲 | 高峰（北京时间工作日 9–12、14–18 点） |
|---|---|---|
| 输入·命中缓存 | 0.02 | 0.04 |
| 输入·未命中缓存 | 1 | 2 |
| 输出 | 4 | 8 |

改在 `~/.dsh/persona-memory.json` 的 `host.budget.prices`（热加载）：

```json
{ "host": { "budget": { "prices": { "hit": 0.02, "miss": 1, "out": 4, "peakFactor": 2, "peakHours": [[9, 12], [14, 18]], "peakTzOffsetMin": 480 } } } }
```

DeepSeek 调价、或者换了模型（允许清单 `host.llm.allow`、各用途的模型 `host.llm.models`）时要跟着改，并更新这里和设计附录 G。价目只用来折算「花了多少」，不做别的判断（比例上限、余额保护用的是折算出来的元）。

## 5. 预设和护栏

效果优先，花费是护栏：正常用的时候后台该做的都照做，护栏只防程序失控（死循环、刷屏的群把调用放大几十倍）和余额被后台吃光。管理页「设置 → 花费护栏」里切换预设、自定义每一项、看每条上限今天用了多少。

### 三档预设

| 项 | 宽松（默认） | 节省 | 不设上限 | 配置 |
|---|---|---|---|---|
| 每天后台调用次数（不含外发审视） | 3000 | 600 | 不设 | `budget.presets.*.dailyCalls` |
| 每天未命中缓存的输入 | 500 万 token | 100 万 token | 不设 | `dailyUncachedTokens` |
| 每天输出 | 100 万 token | 30 万 token | 不设 | 宿主 `host.budget.dailyOutputTokens`（按档；「不设上限」档没有这一项） |
| 一个群或私聊最多占一天未命中输入上限的 | 50% | 30% | 不单独限（100%） | `perSourceShare` |
| 后台花费最多是她聊天的 | 不设 | 25% | 不设 | `mainChatRatioCap` |
| 第二段评估跑在 | 所有拿不准的 | 只在对她说、真正等待、有意回想时 | 所有拿不准的 | `stage2Scope` |
| 预取改写 | 开 | 关 | 开 | `prefetchRewrite` |
| 重排 | 开 | 开 | 开 | `rerank` |
| 夜间整理 | 完整（每晚最多 14 次） | 只做必要项（每晚最多 6 次） | 完整（每晚最多 14 次） | `sleepDepth`；次数见上面「夜间整理」一行（D138） |
| 余额保护：余额不够几天的预计花费时停后台 | 1 天 | 3 天 | 1 天 | `balanceProtectDays`（0 = 关） |
| 回想注入她上下文最多占上下文增量的（最近 50 步） | 25% | 5% | 不限 | `injectShare`（D133） |
| 每个会话每天回想注入 | 不限 | 8000 字 | 不限 | `injectPerSessionPerDay`（D133；D147 起宽松档不限） |
| 被问到以前的事时一次想起来的量（回忆） | 100%（工具 36 条约 4000 字，自动触发 18 条约 2000 字） | 50% | 100% | `recollectScale`（D155，乘 `recall.recollect` 的条数和总字数） |
| 外发审视每天单独留 | 100 次 | 100 次 | 100 次 | `budget.egressReservePerDay` |
| 第一眼超了上限以后的预留 | 150 次 | 150 次 | 150 次 | `budget.glanceReservePerDay` |
| 对她说的一对一提炼超了上限以后的预留 | 每天调用上限的 20% | 同左 | 不按次数限 | 宿主 `host.budget.reservedExtractShare` |

- **宽松**：默认。后台该做的都照做，上限只防失控。
- **节省**：余额紧、或者不需要她在群里想得那么全的时候。代价见第 8 节。
- **不设上限**（D121）：给用得多、不在乎花费的主人（大群多、聊得多，宽松档的 3000 次 / 500 万也会碰到）。调用次数、token、比例都不拦，其余和宽松一样全开；**余额保护照留**（余额不够 1 天时停后台，DSH 报余额用完时也停）。代价：程序真失控了（死循环、刷屏放大）不会被拦住，只能靠余额保护和你看「后台花费」。切到这一档要在页面上确认。

外发审视、第一眼的预留三档都一样，不受预设影响。

**回想注入的两行**（D133）管的不是后台的钱，是插件往她的会话里注入多少记忆（花在她聊天的输入上，第 2 节）。「你想着的」和工作记忆不受限、也不算进已注入的字数；别的层（想起来的、在场者近况、人物卡、时间间隔……）合起来受这两条限：最近 50 步（`context.rolling.steps`）里注入的字数不超过同期上下文增长（每一步比上一步多出来的 token 加起来，压缩让上下文变小的那一步算 0）× 比例，每个会话每天不超过那么多字（宽松档不限每天的字数，D147：比例已经保证注入不超过聊天内容增长的四分之一，再加一个绝对数只会让最活跃的会话先断粮；想要的话在「自定义」里自己设）。超了以后这 50 步里（或当天）只给「你想着的」、工作记忆和被直接问到时的回想。宽松档给得松，记忆效果优先；节省档是 D133 之前的数。旧配置里的 `context.rolling.maxShare`、`context.perSessionPerDay` 已弃用，读到了也忽略。超了几轮、因为预算少给了几条、各会话今天用了多少，在「诊断 → 回想稳定性」里看。

**回忆的量**（D155）也是她聊天的输入，不是后台的钱：被直接问到以前的事、或她调记忆工具时，回想换成「回忆」，一次给的条数和字数比平常多（宽松档自动触发约 2000 字、工具约 4000 字；节省档减半）。它和「想起来的」同一档：被直接问到时不受上面两行的额度限制，但字数照样记进已注入的。回忆不新增任何后台模型调用（读懂问题用的是本来就有的预取改写 `rewrite`，没有改写时只用语言层），也不新增用途。

### 自定义每一项

哪一档都不合适，就在「设置 → 花费护栏 → 自定义每一项…」里从现在的值开始一项一项改：选一档做基础，改的项存成 `budget.overrides`（和那一档一样的项不存），没改的跟着那一档走。保存后立即生效（热加载），管理页的请求日志记一行操作名。卡片右上角写「现在：自定义（以宽松为基础）」，下面列出改过的项和那一档原来的值；点「宽松 / 节省 / 不设上限」任一档就回到那一档，改过的都清掉。

| 键（`budget.overrides` 里） | 是什么 | 调高 / 打开 | 调低 / 关掉 | 管理页能填的 | 配置文件里能写的 |
|---|---|---|---|---|---|
| `dailyCalls` | 每天后台调用次数（不含外发审视） | 忙的日子后台也不停 | 失控时更早停 | 50–1,000,000 次，或不设 | 不小于 0 的整数或 `null`（不设） |
| `dailyUncachedTokens` | 每天未命中缓存的输入 | 群多、话多时提炼不停 | 更早拦住失控 | 10 万–20 亿 token，或不设 | 同上 |
| `dailyOutputTokens` | 每天的输出（比输入贵 4 倍） | 提炼和夜间整理写得下 | 更早拦住失控 | 2 万–5 亿 token，或不设 | 同上；不写时按宿主每档的数 |
| `perSourceShare` | 一个群或私聊最多占每天未命中输入上限的多少 | 一个热闹的群能多用 | 刷屏的群挤不掉别处 | 5%–100%（100% = 不单独限） | 大于 0、不超过 1 的数 |
| `mainChatRatioCap` | 后台花费最多是她聊天的几倍 | 后台能比聊天多花 | 后台跟着聊天量走 | 5%–1000%，或不设 | 大于 0 的数或 `null` |
| `balanceProtectDays` | 余额不够这么多天的预计花费时停后台 | 余额紧时更早停 | 0 = 关掉（余额用完时她的聊天也会停） | 0–30 天 | 0–365 的整数 |
| `stage2Scope` | 第二段评估跑在哪些轮次 | `all`：群里也评估，想起来的更全 | `direct`：只在对她说时，省钱 | 两个选一个 | `"all"` / `"direct"` |
| `prefetchRewrite` | 预取改写（「那个」「他」改写成线索） | 开：指代多的话想得更准 | 关：省一点 | 开 / 关 | `true` / `false` |
| `rerank` | 回想的候选再排一次序（本机算，不花模型钱） | 开 | 关：排序差一点 | 开 / 关 | `true` / `false` |
| `sleepDepth` | 夜间整理做多少 | `full`：泛化、反思、社区、日记、自我概念都做 | `essential`：只做必要项，她长进得慢一些 | 完整 / 只做必要项 | `"full"` / `"essential"` |
| `injectShare` | 回想注入她上下文最多占上下文增量的多少（最近 50 步） | 想起来的给得更全 | 她聊天的输入少一点 | 1%–100%，或不限 | 大于 0、不超过 1 的数或 `null`（不限） |
| `recollectScale` | 被问到以前的事（回忆，D155）时一次给她的条数和字数，乘 `recall.recollect` 两档的数 | 答得更全 | 她聊天的输入少一点 | 10%–100% | 0.1–1 的数 |
| `injectPerSessionPerDay` | 每个会话每天回想注入多少字 | 聊得多的会话也一直有记忆 | 她聊天的输入少一点 | 1000–1000 万字，或不限 | 不小于 0 的整数或 `null`（不限） |

上限不设（`null`）时这里按无穷大执行：未命中输入不设上限时，「一个群最多占多少」也不起作用；调用次数不设上限时，对她说的一对一提炼的预留不按次数限。

**手改配置文件**（`~/.dsh/persona-memory.json`，热加载，一分钟内生效）：

```json
{ "budget": { "preset": "loose", "overrides": { "dailyCalls": 10000, "dailyUncachedTokens": 20000000, "dailyOutputTokens": 5000000, "sleepDepth": "full" } } }
```

- 写错的那一项（不认识的键、类型或取值不对）忽略，其余照用，启动和热加载时记一条 warning（插件日志里）。
- **有风险的改动先扣下**：配置文件里换成 `"preset": "unlimited"`、把 `dailyCalls` / `dailyUncachedTokens` / `dailyOutputTokens` 写成 `null`、把 `balanceProtectDays` 写成 `0`，热加载时先不生效（照原来的跑），管理页「设置」顶上出现「配置文件里有还没生效的改动」，你确认了才生效，或者丢弃。在管理页上做同样的改动会先弹确认框；已经是这样的（例如余额保护已经是 0、只是改了别的项）不再问。

还有：后台队列连续失败按 1 / 4 / 16 分钟退避（`host.llm.backoffMin`），提炼和夜间整理一次一个、两次至少隔 5 秒。一段对话的提炼重试用完了还不成（D136），这一段搁置起来，之后一轮只试一次、隔得越来越久（一时出错的从 30 分钟翻倍到最多 12 小时，输出不合格、内容被拒的从 6 小时翻倍到最多 7 天，`extract.stalled`）：一段卡住的对话一天最多多花几次提炼调用，不会每隔几分钟重试一次。输出被上限截断的段（D141）拆小重做，不原样重试（原样重试只会再截断一次）；一条消息还截断的直接搁置。截断了几次、拆了几次在管理页「诊断 → 记忆库」的「提炼一直不成」那一行（最近 7 天）。

**到了上限会怎样**（第二天零点清零）：

- 提炼、夜间整理、第二段评估、改写、看过的媒体当天先停。她收到的消息照常存、照常想得起来（原话能检索）；提炼的任务推迟，不丢。对她说的一对一的话的提炼和第一眼还留着一小份。
- 第二段评估停了：拿不准的那几条先不给她，第一段放行的照常给，她不会因此不说话。
- 外发审视的预留用完：公开场合要送审的那句改口、不发出去（fail closed）。
- 被挡下的次数按用途和原因记着，管理页「花费护栏」最下面一行。

**余额保护**：余额不够「预计每天花费 × N 天」时（N 见上表），或者 DSH 报余额用完（402）时，后台只剩外发审视；充值后自动恢复（有余额来源：读到余额大于 0；没有：停 20 分钟后放一次试试）。停着期间存下的消息之后补提炼。每天花费按整个账户估（后台 + 所有会话，最近 7 天平均；有连续的余额读数时再和「余额每天掉多少」取大的）。余额要在私有配置里接一个余额来源（`host.budget.balance.file` / `path`）才知道；没接时管理页写「没接余额来源」，只有 402 触发。

## 6. 在管理页哪里看

- **总览 → 后台花费**：今天后台估算花了多少、她的聊天花了多少、后台相当于她聊天的百分之几、今天的调用次数对着上限、被挡下几次、余额还够几天；「看明细」跳到设置。
- **设置 → 后台花费**：今天按用途的表（次数 / 失败、未命中输入、命中输入、输出、约多少元）和合计；最近 30 天每天一行（后台和她的聊天同一把尺子）和合计；后台占她聊天和整个账户的多少；这些数准不准、价目在哪改。
- **设置 → 花费护栏**：预设开关（宽松 / 节省 / 不设上限）、「自定义每一项…」、改过的项、每条上限今天用了多少（不设上限的写「不设上限」，不画进度条）、超了会怎样、今天被挡下了什么。
- **诊断 → 回想稳定性**：回想注入超了每天 / 滚动窗口额度的轮数、因为预算没放进去的条数、各活跃会话今天已用 / 上限和滚动窗口已用 / 上限（D133）。
- **诊断 → 夜间整理**：上一次夜间整理调了几次模型、总上限多少、哪几步因为上限少做了（顺延到下一晚），泛化问了几组 / 归纳出几条 / 问过没变跳过几组，日记写了几天、还缺几天（D138）。
- **诊断 → 后台预算 / 后台模型**：上限的进度、失败的调用；后台模型那张是这次启动以来的调用次数、排队和最近的错误。


## 8. 想再省一点

- **切到节省档**（管理页「设置 → 花费护栏」）：第二段评估只在对她说时跑、改写关掉、夜间整理只做必要项，还加上「后台最多是她聊天的 25%」，回想注入收到最近 50 步上下文增量的 5%、每个会话每天 8000 字。代价：群里拿不准的记忆更常先不给她，指代多的话想起来差一点，聊得多的会话里记忆更早只剩「你想着的」和工作记忆。
- **看哪一项最多**：「后台花费」的表按用途分开，元最多的那一项就是该动的。第一眼的量跟着热闹的群走；不需要她在某个群里记事，可以在「场合与规则」把那个群关掉（关掉的场合不感知、不注入，也就不提炼、不看第一眼；她在那里就什么都不记了）。
- **单独压某一项**：「花费护栏 → 自定义每一项…」（或者 `budget.overrides`）里把每天上限调低（例如每天调用 1500 次），或者把余额保护的天数调高，让余额紧的时候早一点停后台。
- **反过来，用得多、不在乎钱**：切到「不设上限」，或者在自定义里只把碰到的那一项调高（今天被挡下了什么写在「花费护栏」最下面）。
- **输出比输入贵 4 倍**：提示词改动时让模型只输出结构化的结果；输出约占后台花费的四成。
- **缓存命中只要 1/50 的价**：提炼的固定前缀已经能命中；新增用途时把不变的说明放在提示词最前面。
- 别把后台换成 `deepseek-v4-pro`：同样的量要贵 3–4 倍（允许清单默认只有 `deepseek-flash`）。
